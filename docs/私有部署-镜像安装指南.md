# WarmCore 私有部署 · 镜像安装指南

> 部署模式：**拉官方镜像**，不需要源码、不需要构建工具。
> 镜像不可变；你的数据（AI 对话/相册/记忆）全部存在本机 Docker 卷中，升级不丢。

## 一、前置要求

- Docker 20.10+ 与 docker compose v2（`docker compose version` 能执行即可）
- 内存 ≥ 4GB，磁盘 ≥ 20GB
- 模型自备：本机已运行 [ollama](https://ollama.com)（**镜像不内置任何模型**，WarmCore 只连地址）
  - Linux 用容器跑 ollama 的话：`docker run -d --name ollama --gpus all -v ollama:/root/.ollama -p 11434:11434 ollama/ollama`
  - 然后拉一个对话模型：`ollama pull qwen3:8b`

## 二、一条命令安装

```bash
curl -fsSL https://raw.githubusercontent.com/zhouyevip/WarmCore/main/install.sh -o install.sh
bash install.sh
```

脚本会依次：检查 Docker → 下载官方编排文件 → 交互收集配置（自动生成 64 位随机密钥）→ 生成自签证书 → 拉镜像启动。
国内下载 GitHub raw 慢时，加加速前缀：

```bash
DOWNLOAD_BASE="https://ghfast.top/https://raw.githubusercontent.com/zhouyevip/WarmCore/main" bash install.sh
```

装完会打印访问地址（默认 `http://<局域网IP>:8080/` 部署门户、`/admin` 家庭后台）。

手工安装（不用脚本）等效步骤：

```bash
mkdir warmcore && cd warmcore
curl -fsSL https://raw.githubusercontent.com/zhouyevip/WarmCore/main/docker-compose.release.yml -o docker-compose.release.yml
curl -fsSL https://raw.githubusercontent.com/zhouyevip/WarmCore/main/Caddyfile.private -o Caddyfile.private
# 手写 .env（HUB_JWT_SECRET 用 openssl rand -hex 32 生成）
docker compose -f docker-compose.release.yml up -d
```

## 三、配置说明（.env）

| 变量 | 说明 | 默认 |
|---|---|---|
| `WARMCORE_VERSION` | 镜像版本，`latest` 跟随最新；填 `v1.2.0` 锁定版本 | `latest` |
| `WARMCORE_REGISTRY` | 镜像源，国内拉 ghcr 慢时可切换镜像源 | `ghcr.io/zhouyevip` |
| `HUB_JWT_SECRET` | JWT 密钥（install.sh 自动生成，**勿外传**） | 必填 |
| `CLOUD_URL` | 云端总管地址（绑定/同步目标），留空=纯本地运行 | 空 |
| `OLLAMA_BASE_URL` | ollama 地址；宿主机运行保持默认即可 | `http://host.docker.internal:11434` |
| `DIGITAL_HUMAN_ADVERTISE_HOST` | 宿主机局域网 IP（手机访问二维码/数字人用） | 自动探测 |

> Linux 提示：compose 已给 app 加 `host.docker.internal:host-gateway` 映射，宿主机 ollama 开箱可用。

## 四、更新与回滚

**检查更新**：家庭后台 → 「检查更新」页（`http://<IP>:8080/admin/update`），显示本机版本 vs 最新版本与更新内容。

**一键更新（推荐）**：检查更新页发现新版本后，点「一键更新」按钮——系统自动拉取新镜像并重启业务容器（约 1~3 分钟），期间服务短暂中断、页面自动恢复。数据全在本机卷中不受影响。更新依赖 `auto-update`（watchtower）服务在运行，且宿主机已 `docker login ghcr.io`（Private 镜像需要）。

**命令更新（等效）**：在部署目录执行：

```bash
docker compose -f docker-compose.release.yml pull && docker compose -f docker-compose.release.yml up -d
```

**锁定/回滚版本**：改 `.env` 里 `WARMCORE_VERSION=v1.1.0`（换成任意历史 tag），再执行上面同一条命令。数据卷不动，只换镜像。

## 五、数字人（可选，GPU）

- **生成服务**（照片→说话循环视频，LivePortrait）：

  ```bash
  docker compose -f docker-compose.release.yml --profile digital-human up -d
  ```

  镜像只含代码；LivePortrait 权重与动作模板按 `digital_human_service/deploy.md` 准备后放入 `./data/digital-human/`（服务在模型缺失时会以 degraded 状态启动，`/health` 可排障）。

- **贾维斯完整语音+口型栈**（s2s + LiveTalking，进阶）：依赖参考包镜像（`docker-ai-gf-s2s` / `docker-ai-gf-avatar`）与数据包，未备齐勿启用：

  ```bash
  docker compose -f docker-compose.release.yml --profile digital-human-gpu up -d
  ```

## 六、常见问题

- **镜像拉取慢/超时**：`.env` 设 `WARMCORE_REGISTRY=<镜像源地址>` 后重新 pull（阿里云 ACR 同步源后续提供）。
- **手机访问不了**：确认 `DIGITAL_HUMAN_ADVERTISE_HOST` 是电脑真实局域网 IP，路由器未隔离无线设备。
- **对话无回应**：ollama 未启动或模型未拉取；`curl http://<IP>:11434/api/tags` 自检。
- **看日志**：`docker compose -f docker-compose.release.yml logs -f app`（或 admin_server / caddy）。
- **数据在哪**：Docker 卷 `warmcore-app-data` / `warmcore-mongo-data` / `warmcore-minio-data`；备份 = 备份这几个卷，删除容器/镜像不影响数据。
